## The steer 0x7840c / 0x77d28 (2026-10)

Research agent, 2026-10-05, static read with `efx/armdis.py`; cross-checked in unicorn (below). Everything here is
**READ** unless marked INFERRED. P = `[e+0x1428]`; angles are u16 words (0x10000 = 360 deg).

**The call site (`0xdcbf20..0xdcbfc4`, ph1, every update after ph0 while tune 0x26 > tune 0x25, `0xdcbf58`):**
`0x7840c(e, r1 = uxth(910), r2 = uxth(0x8000) [(7,0xe2): uxth(0x8000 + s32(0.5 + tune 0x29 × 182.044)) = 0x838e],
r3 = 0, s0 = tune 0x25 (50.0), s1 = tune 0x26 (56.0), s2 = 150.0 (literal `0xdcbfb0`))`. No stack arguments: `0x7840c` is
`b 0x77d28` and `0x77d28` reads only its own locals at `[sp]`, `[sp+4]`. The return value is ignored (`0xdcbfc8`).
So: r1 = the rate (units per frame of motion step), r2 = the aim offset added to the target bearing, r3 = the facing
offset of the "is the target behind me" test, s0..s1 = the motion-frame window, s2 = a travelled-distance threshold.

**The setup `0x782e4(e, mode r1, offset r2, flags r3, [sp] = threshold)`, `0x782e4..0x783f4`:**
`P+0x5e64` = mode (byte), `+0x5e65` = state 0 (byte), `+0x5e66` = 0xff then the side, `+0x5e68` = flags (word),
`+0x5e6c` = 0.0 (the travelled sum). Side: diff = uxth(offset − yaw + s32(0.5 + atan2f(dx, dz) × 10430.378)) with
dx, dz = `P+0x1d0` − `P+0x40`, `P+0x1d8` − `P+0x48`; when flags bits 0 / 1 are set and |diff| (folded at 0x8000) ≥ the
stack threshold, side = 0 (bit 0) or 1 (bit 1) and the flags stay; otherwise side = diff bit 15 and flags bits 0..1
are cleared (`bfc`). Rustrazor: mode 2, flags 0, threshold 0 → side = bit 15, flags 0.

**`0x77d28` (`0x77d28..0x782dc`), per call:**
1. state = `P+0x5e65`. state 1 → return 1 with no turn unless mode = 1 (`0x77ecc`; mode 1's state-1 path turns
   by side, below). Any state other than 0 / 1 (the resets write 0xff) → return 0, no turn.
2. state 0, flags bit 2 clear: `P+0x5e6c` += |`P+0x320..0x328`| (vsqrt, `sqrtf` on NaN). INFERRED: `+0x320` is the
   unit's displacement this update (`0xa61bc` writes it as `P+0x40..` − `P+0x00..`, `0xcc890` adds to it; `P+0x00`
   not identified). When the sum > s2 (150.0): facing = (sinf(a), 0, cosf(a)) with a = uxth(yaw + r3) × 2π/65536;
   dot = facing · (target − position) (`P+0x1d0..` − `P+0x40..`). dot < 0 (or flags bit 3) → mode 2: when
   dx² + dz² < 22500.0 (`0x7828c`; 90000.0 at `0x78288` when flags bit 4), state = 1 and this update steers at
   rate 0 (`0x780b4`): **the steer stops for good once the unit has travelled more than 150 and the target is
   behind it within 150 horizontally.** Mode 1 at that point turns by side (`0x77fa4`). Otherwise fall through.
3. The steer (`0x780b8`), by flags: bit 0 → `0x77b54(e, 1, ...)` (forced +), bit 1 → `0x77b54(e, 2, ...)`
   (forced −); f0 < 0 (the entry `0x783fc` passes f0 = f1 = −1) → no window: yaw = `0xc0dbc(e, uxth(T + offset),
   yaw, rate)`, a clamp toward the aim by u32(rate × `[e+0x1c]`) (`0xc7258`, called first, is `bx lr`); else
   (Rustrazor) → **`0x770e4(e, rate, offset, 0, f0, f1)`**, its result returned.

**`0x770e4(e, rate, offset, target slot, f0, f1)` (`0x770e4..0x772a0`):**
- `0xb0968(e, 9, &share, f0, f1)` (mode 9, rom-map `0x729fc`): no overlap of this step with [f0, f1] → return 0.
- step s: normally `ceil(rate × [e+0x13b8] × share)` (`vcvtp.u32`), then uxth. The catch-up branch instead adds
  s32(0.5 + rate × [e+0x13b4] × max([e+0x4fc] − f0, 0) / ([e+0x4fc] − [e+0x13b0])) to the rounded normal part; it
  runs only when `0xb0a90` (gate `+0x4f4` ≤ 0 and byte `+0x13f0` ≠ 0) and `[e+0x13c0]` bit 0 is clear. `+0x13f0`
  is "gate > 0" taken at the update's snapshot (`0x71a84`, `0x5393b0`), `+0x13b0` the frame `+0x4fc` then
  (`0x71a78`): the part of the window missed while the gate held. The viewer has no gate, so never.
- T = s32(0.5 + atan2f(tx − x, tz − z) × 10430.378) (truncation toward zero), target slot 0 = `P+0x1d0`.
  d = s16(offset − yaw + uxth(T)).
- |d| < s → yaw = uxth(T + offset), return 1 (the aim is reached and snapped). Else yaw = yaw + s when d ≥ 0,
  yaw − s when d < 0 (the shorter way; d = −0x8000 goes −), stored as the full word (no uxth), return 0.
- **P+0x5e66 (the side) is not read on this path**: for mode 2 it is computed and unused. The aim and the
  direction are re-derived from the target's position on every update.

**Formula for the viewer (Rustrazor (7,0xdf) / (7,0xe2), L9 M20):** at the action's first update acc = 0,
stopped = false. Each later update, with the layer-0 frame pair (prev, cur], the unit's x, z, displacement d3 and
yaw Y (u16), the proxy target tx, tz, R = 910, O = 0x8000 (0xdf) or 0x838e (0xe2), f0 = 50, f1 = 56:
```
if stopped: no turn
acc += |d3|
if acc > 150 and dot((sin Y', 0, cos Y'), target - pos) < 0 and (tx-x)^2 + (tz-z)^2 < 22500:
    stopped = true; no turn                                  # Y' = Y * 2pi / 65536
if not ((f0 <= prev <= f1) or (f0 <= cur <= f1)): no turn   # mode 9
share = max(0, min(cur, f1) - max(prev, f0)) / (cur - prev)
s = ceil(R * (cur - prev) * share) & 0xffff
T = trunc(0.5 + atan2(tx - x, tz - z) * 65536 / (2 pi))
d = s16(O - Y + (T & 0xffff))
Y = (|d| < s) ? (T + O) & 0xffff : (Y + sign(d) * s) & 0xffff   # sign(0) = +, d = -32768 goes -
```
At step 1.0 the window turns on the six updates (50,51] .. (55,56]: at most 6 × 910 = 5460 (30.0 deg), toward
"back to the target" (+5 deg for 0xe2), snapping when within 910. No random number, no hunter-only state, no
network-owner test is read anywhere in `0x77d28` / `0x770e4` / `0x782e4`; the inputs are the target position, the
unit's position, displacement and yaw, and the motion frame (plus the gate the viewer does not have).

**Who else reads the block:** `0x77a2c` (yaw ± u32(r1 × `[e+0x1c]`) by the side `+0x5e66`, called from uEm007's
`0xd43394`); `0x78410` (the sibling after `0x7840c`, reads `+0x5e64..+0x5e70`, NOT READ); uEm007's own copy
`0xd43170` (NOT READ); uEm087/88 `0x10bbaf0` (state 0, sum 0). Resets: `0x6ea7c..0x6ea90` (flags, sum, `+0x5e70`),
`0xad278..` and `0xba60c..` (mode 0, state / side 0xff [`0xba5ac`; `0xad28c`'s r8 not traced], flags / sum /
`+0x5e70` 0). `0x1e5884` is `+0x15e64` (movt #1), another field. libm stubs, resolved through the PLT relocations:
`0x13ecba8` atan2f, `0x13ecc14` sqrtf, `0x13ecc20` sinf, `0x13ecc2c` cosf.

**Cross-check (unicorn, scratch `steer_uc.py`, not a source):** `0x782e4` then `0x7840c` run for real (frame query
`0x72714` included, only the libm stubs hooked), 70 updates × 8 cases (far / near targets, both offsets, moving
with the target ahead, moving past the target, aim reached inside the window): yaw, return and state matched the
formula above on every update, 0 mismatches. The pass-the-target case latched state 1 at f38 and never turned.

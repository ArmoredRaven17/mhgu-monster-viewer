# Fatalis (em013_00) and Crimson Fatalis (em013_01) — when the beam fires

One class, `uEm013_00` (vtable `0x17a5a24`, action main `0xd8a634` = vtable +0x1f4, band `0xd7d578..0xd8e1c0`), the
variant byte `e+0xb5f5` choosing the monster: 0 = Fatalis, 1 = Crimson Fatalis, 2 = em013_02. Beam shells
`uShellEm013_00_02` **0x84**, `uShellEm013_01_02` **0x88**, `uShellEm013_02_02` 0x8c — written as LITERALS by the one
spawner, picked by the variant. Beam research agent A, 2026-09-30. Method and positive control (Basarios's beam
reproduced through the same harness): `dev/beams/em005_00.md` section 5. Both monsters play list 2 from the same file
`em013_00_2` (docs/monsters.json: em013_01's list 2 is `shared`).

**The aim, `0xd81e80(e, L, &v, s0)` — READ (`0xd81e80..0xd82018`).** size = `0xbe518(e)` (the monster's size, rom-map
row); v = (0, 250, 800) x size, turned by the owner's angle words `P+0x58` (Z), then `P+0x50` (X), then `P+0x54` (Y)
(u16 x 9.58738e-05 rad; `sinf` `0x13ecc20`, `cosf` `0x13ecc2c`): `a = vy cosZ + vx sinZ`, `b = vx cosZ - vy sinZ`,
`c = vz cosX + a sinX`, `y' = a cosX - vz sinX`, `x'' = b cosY + c sinY`, `z'' = c cosY - b sinY`; the mouth point
M = `P+0x40..0x48` + (x'', y', z''). Then d = (T.x - M.x, **T.y + 380.0** - M.y, T.z - M.z) with T = the target
`P+0x1d0..0x1d8`; pitch = `atan2f(-dy, sqrt(dx^2 + dz^2))` (`0xd81fc4`); w = s32(0.5 + pitch x 10430.4); u = u16(w).
**Clamp to +-L = +-0x18e4 = +-35.0 deg**: u < 0x4000 and u > L -> L; u >= 0x4000 and u < 0x10000 - L -> 0x10000 - L;
else w (`0xd81fd0..0xd8200c`). Returns u16. So r2 = 1 aims the beam's pitch at a point 380 above the target, from a
point 250 up / 800 forward of the body; r2 = 0 fixes it at 4 deg.

**The rest of the action.** Phase 0 (`0xd865dc`): `P+0x1a1 = 1`, `0xbc7f4(e, 0)`, `P+0x1bb = 1` (`0xd86608`), the
motion, then `0x7ded8(e, 0, 0xe)` (a hit record, tail `0xd86628`). Phase 1 (`0xd8662c`): window op 3 (90, 120) ->
`0x76c08(e, 0xb6, 0)`; f94 the beam; at the motion's end `0xbc7f4(e, 0)`, `0x75230(e, 1, 2)` (set action (1,2)) and
`0x82454(e, 0)` (`0xd86800..0xd8683c`).

**em013_02** (variant 2) makes 0x8c mode 0 at the same frame (`0xd86734..0xd86758`), but its mode 0 carries ef
`[999, -1]` — no effect, no BEAM_TYPES entry. Not one of this lane's monsters; noted because it shares the code.

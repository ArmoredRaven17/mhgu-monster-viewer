shell48 (Ahtal-Ka's ballista balls) -- base48 + uShellEm088_sp_48 + the spawn + the CU request bytes.
Research agent, 2026-10-15, static reads (sdis.py). READ = the consuming instruction was read; INFERRED / NR said where they stand.
Disassembly kept beside this file: band.txt (base48 0x426600..0x427b00), sp48.txt (0x10c4100..0x10c4600), spawn.txt
(0x10b345c..0x10b3f00), cu.txt (CU band 0x10ad9f4..0x10aef00), sp01.txt + x10c3f50.txt (sp_01), x10b6320.txt, x1f5c10.txt,
x43b2b0.txt, x4a1430.txt.

Notation: S = shell; dt = float S+0x1c; every VFP op rounds to float32. vmla d,a,b = d + a*b (product rounded, then sum
rounded -- two roundings, as everywhere in shells.js `mla`); vmls d,a,b = d - a*b. U = 10430.378 (lit 0x4622f983),
R = 9.58738e-05 (0x38c90fdb). ang(x) := u16(trunc(vmla(0.5, x, U))); rad(w) := f32(w as u32) * R.
rotY(v; w): sn = sinf(rad w), cs = cosf(rad w); x' = vmla(v.x*cs, v.z, sn); z' = vmls(v.z*cs, v.x, sn); y unchanged.
atan2f is 0x13ecba8 called (s0, s1) = (dx, dz), the same convention shells.js uses (atan2f(dx, dz)).

 So 0x1f5c10 is not a quest / stage / gimmick script: it is the network receive handler of the Neset/Ka control unit's
 "free use" packet, commands 3 / 4 = "ballista 0 / 1 fired at hunter a". The local trigger is C.

 How many / how often: ONE shell48 per cut line. Locally +0xc6+k = 1 is written and read in the same vt+0x1dc call and
 P+0x1bb bit k is cleared, so line k can fire again only after 0x10b6320 makes shell01 mode k again (E+0xd3fc, EMC op
 0xa3 b1 2 per the props spec). Both k may fire in one frame. Remote copies get 2: one shot if the CU's move (E) runs
 before Ka's vt+0x1dc in the frame, two if after -- the unit-line order of the CU is NR.
 E+0x7420: written 0 at 0xaf2cc, 1 / (own index == r1) at 0xb1590..0xb161c (with E+0x7424 = an index from 0x495d8 /
 0x4957c); INFERRED the "this machine runs this enemy" flag (1 offline); not read further.

 Viewer: nothing corresponds. The ROM's trigger needs a hunter striking a shell01 mode 0/1 line (a hit-slot event) and
 a hunter's position for the target; the viewer has neither hunters nor the hit side. The ROM-derived parts that ARE
 available: line k exists (shell01 mode k, P+0x1bb bit k), the start (tune vec 13 + k), the flight (section 1). A
 reproduction needs two inputs with no ROM value: "line k was cut" (the event) and the target point (the cutting
 hunter's position; or (0,0,0) world origin only when that hunter fails 0xafa10 -- still after a cut).

## 1. The shared mechanism (READ: dev/rom-map.md "GU Hyper"; decode note shared-state-effects.md 9, Rathian)

- **The flag**: e+0xb720, written by the ctor (0) and **vt+0x170 = 0xca664** (= 1; e+0xb722 = a u16 seed), called by the spawn setup
  0x6fa58 when **byte +0xb of the quest's monster entry** is set (0x3a964c copies the entry). Never cleared.
- **The data**: vt+0x150 = 0xca68c attaches an **rEmDouMouKaData** (`enemy\dou_mou_ka\<id>_doumouka.mdd`, and a `_g.mdd`; which
  of the two loads -- the resource id is hashed -- is NOT READ; four monsters' files differ: Congalala, Rajang, Nerscylla, Malfestio).
  - **PartsAuraData**: per aura `DouMouKaID`, `SpecificPartsGroup` (0 / 1), `SpecificParts` (the part), the part biases
    (PartsVital / KariWaza / Support / MeatChange) and `MeatChange_Group[4]` (hit-zone groups).
  - **PartsChangeData**: HP-rate steps, each with an action (Rathian: 0.8 / 0.6 / 0.4 / 0.2 with (1, 9), the rage roar).
  - **ModifyData**: per aura ID, actions with MotionSpeedRate / Limit / AttackRate / PowerRate, and shell elements.
  - **BuiFirstRandomFlag**: the first aura of each group random (else the first in the list).
- **The auras**: 0xca1f8, per group g = 0 / 1: the next aura of that group (the first: index 0 or random by the seed; after: the next in
  the list, wrapping), the old handle stopped (0x329c40(h, 0)), **u id 47 + DouMouKaID** requested (the base u table 0x159c7fc: 47..52
  -> **u 1300..1305**), requester mode 3; held at e+0xca8c / +0xcaa0. Called at the data attach, at the (re)init (0xca1d8 from
  0xb8b98), and by setAction through vt+0x194 = 0xca980 when the HP ratio passes the next PartsChange rate and the new action is that
  step's (Rathian (1, 9)). **One aura per group at a time; both groups step together.**
- **Visibility**: vt+0x1a0 = 0xca508 writes both handles' +0x1c1 from the drawn test each frame (0xa5ec0).
- **Bursts**: 0xca4e0(e, id) = **u 53 + id -> u 1310 + ID** -- per-class hooks at motion frames (Rathian: vt+0x478 / +0x490, with motion
  rate changes 0xb07b4). Animation side: HELD.
- **The part biases**: 0xca6b0 / 0xca754 / 0xca830.. (accessors): the aura's SpecificParts bias when the asked part is the hyper part,
  else the OtherParts bias. **MeatChange** (bias and groups) -- its consumer is NOT READ, so no hit-zone change is built.

## Read 2026-10-25: which file, and the meat change

* **Which .mdd loads (R).** The loader `0x4bd64` takes resource column 0x26 when e+0xb736 is 0, 0x27 otherwise; e+0xb736 is
  (quest rank `0x3a8430` > 4), written at `0x6f1c0..0x6f1d8`. The monster's .rodata resource list holds both paths (Rathian
  `0x15d99d0`: `..._doumouka`, then `..._doumouka_G`). So the `_g.mdd` is the G-rank file. docs/hyper-auras.json now carries both
  (`normal`, `g`; `<archive>/cen/mkhyperauras.py`) and the Hyper row reads the Quest Rank's. Congalala (em021_00) and Nerscylla
  (em070_00) have empty plain files: their auras exist at G only. Rajang (em023_00) and Gore Magala (em079_00) group differently.
* **The meat change (R).** vt+0x18c = `0xca900(e, slot)`: hyper, both group auras held, the slot in a held aura's MeatChange_Group
  -> its MeatChange_SpecificParts_Bias, else 1.0. Read by the deflect classifier `0x16d800` (cut and impact x the bias: the
  Hardness) and the two shot paths `0x171164` / `0x178298` (shot + the bias). No damage path reads it. **Built**: the Hit Zones'
  Hardness grades the body's slots with it while a Hyper pair is held (index.html hyperMeatBias). Biases above 1 exist on 20
  monsters (1.1..1.5); the shot term is not shown (the viewer grades blades).

## 6. The motion side -- BUILT (hyper-motion lane, 2026-10-27; rom-map "GU Hyper -- the motion side"; engine doc E26 (g))

Raven, 2026-10-27: "Okay, now for the Hyper Animations. This should modify existing animations based on what set of hyper parts are
enabled". While a Hyper pair is held the PLAYED clip changes -- its speed and its bursts. Nothing is joined, sequenced or replaced.
Tools: `<archive>/hypermotion/` (hookemu.py, modmotions.py, mkhypermotion.py, mkdoc.py, motionmeter.mjs, run.sh / rcd.mjs on port
5791, mountcheck.mjs, hmdis.py).

### 6.1 What the ROM does (READ)

- **The class hooks (rates and bursts).** vt+0x1ec (below G: run by the action main 0xa5b84 when e+0xb736 == 0) and vt+0x1f0 (G: the
  running frame 0xae0e4..0xae100, before the motion advance). 40 classes override them (uEnemy's 0x6be54 / 0x6be58 are empty). Each
  dispatches on the em / variant (uEm001_00 0xd09614 / 0xd096c4 on e+0xb5f4 / +0xb5f5: Rathian vt+0x478, Gold +0x47c, Rathalos
  +0x480 then +0x488, Silver +0x484 then +0x48c, G the +0x490.. set; uEm004_00 0xd2e64c / 0xd2e67c on the u16 **e+0xb5f0**), then
  loops over the two slots (e+0xca88 + 0x14 g, the held DouMouKaID) and switches on the motion id e+0x4b4. On frame tests it calls
  **0xb07b4(rate)** -- P+0x398, a factor of the layer speed (status x P+0x38c x P+0x394 x P+0x398), which setMotion 0xafce8 puts
  back to 1.0 (0xafd3c): a rate holds to the motion's end -- and **0xca4e0(e, ID)** = u 1310 + ID (the record's own joint). The
  tests: below G 0xb0974 (0x72714 mode 0, a crossing prev < f <= cur); at G the rates use 0xb098c (mode 1, cur >= f: re-set every
  frame) and the bursts 0xb0974. Per frame slot 0's calls come before slot 1's; the last rate wins.
- **How it was read.** Not by hand: `hookemu.py` runs each class's dispatcher under unicorn -- class code native (>= 0xcec000), every
  shared call stubbed and LISTED (no hook of the 44 monsters calls any: no rage / tired / ctl gate), the motion getters and the
  predicate entries native into 0x72714, which is answered from a swept clip clock (prev = t - 1, cur = t). Motions L0..L9 x
  M0..M199, each aura ID alone in its group's slot (`table`, with the bl call sites), then each pair the viewer can hold (`pairs`,
  the viewer's data). Positive control: Rathian's table is decode note 9's exactly, below G and at G.
- **ModifyData's action speed.** At every action set (0x767c8, after e+0x73e0 / +0x73e1 / the roll e+0x73e8) vt+0x16c 0xc9e88: with
  BOTH groups' ActionElements held (e+0xca94 / e+0xcaa8, set by 0xca1f8 from data +0x60 / +0x6c), group 0's entries then group 1's,
  the first with the new action's (ActionStatus, ActionNo) and roll % 100 < Rate -> e+0xb724 = MotionSpeedRate, e+0xb728 = its Limit
  (e+0xb72c AttackRate, e+0xb730 PowerRate, e+0xb734 PlHealVital_SpecificRemain: not visual). Then vt+0x368 0xc046c: P+0x38c = base
  x e+0xb724, clamped to e+0xb728 -- the factor every setMotion of that action starts at (0xafdd0) and 0xb07b4 multiplies. Every
  Rate in the 86 non-empty files is 100; no MotionSpeedRate exceeds its Limit at base 1.0.
- **ShellElements** (ShellClassNumber, AttackRate, ScaleRate; e+0xca98 / +0xcaac): the shell hit registration 0x43a8b0 / 0xcaa30
  scales and re-powers a shell whose +0x15bc (its setup's ID) is a held ID and whose base class number +0x15a8 matches (rom-map row
  `0x43a8b0` second half). 45 of the 86 files carry entries (25 monsters; Rathalos ID 1: classes 0 / 1 at x1.3 / x1.5).
- **Not hyper motion (named).** `0xf02b9c` is NOT a hyper attack hit-group site: its byte is e+0xcb14 (rom-map Withdrawn, trap 174).
  `0xfaf210` (Gore Magala, e+0xb5f0 == 0x47): while hyper, the held auras' PartsAura byte +6 (SpecificParts) is swapped 7 <-> 0 by

### 6.5 ShellElements -- built (shells lane, 2026-10-27; rom-map "Hyper ShellElements -- who carries the aura ID" / "-- APPLIED")

- **Who gives a shell its aura ID.** The shell base ctor 0x43a78c sets +0x15bc = -1. Seven base inits copy an aura field into it (base00
  +0x1620, base01 +0x1610, base07 / 12 / 56 +0x15fc, base13 +0x1634, base54 +0x1630), and only the CLASS READER writes that field, from a
  ShellParam int. Of every class of the 25 monsters with ShellElements, seven readers do: Lagiacrus sp_01, Nerscylla sp_00 / sp_00_02 /
  sp_01 / sp_13, Astalos sp_01, Zinogre sp_18; with each mode's own ints the IDs are Lagiacrus 5 (1 on modes 20 / 21), Nerscylla 2 / 4,
  Astalos 4 / 3 (modes 0 / 1); Zinogre's and Nerscylla sp_13's are 0 / -1 (no aura). The other monsters' listed elements never apply.
- **What it does.** +0x60 = ScaleRate (the unit: its effects' parent, over the requester's ShellScale), each hit slot's scale = ScaleRate x
  ShellScale, the power x AttackRate (not visual). Applied in render/shells.js hyperShellElement while the pair is held, the Quest Rank's
  file (index.html shellExtra `hyperShells`); dev/shells-hyper-check.mjs. Metered on the page: Lagiacrus x1.1 (G), Nerscylla x1.6.

**Correction, 2026-10-27 (shells lane; Raven: "It also impacts shell effects, check Khezu").** The aura ID -1 is not "no aura":
